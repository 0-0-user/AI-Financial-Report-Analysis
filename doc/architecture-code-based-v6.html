1. 核心设计原则

系统最核心的约束是隔离数值幻觉：大模型只做语义理解，代码负责一切确定性数学。

大模型做的事代码做的事
理解年报原文、表格表头归类、附注定位提取数字、单位换算（元/万元/亿元）
行业定性标签的兜底补充标签查表（申万 CSV）、同行匹配（余弦）
逻辑推演：异常原因路1查原文 / 路2外部假设勾稽校验（会计恒等式）、MAD 偏差、B+ 逻辑检查
语义合并、冲突标注、语义三档映射D-S 证据理论 mass/合成/概率、E1 置信度打分

含义：任何一处"数学"都不会交给 LLM；反之规则无法覆盖的语义判断不写死规则，交给 LLM。

4. 各层详解与阈值

4.1 L0 — PDF 提取（layer_0_extract）

分工：MinerU（免费版单次 ≤200 页）优先 → pdfplumber 降级 → OCR 纠错 → 规则切四大区块 → 产出 RawDocument。含一次 LLM（表格分类），并非纯工具层。

4.1.1 TOC 拆分（>200 页时，toc_splitter.py）

常量值含义
max_pages200MinerU 单次上限；≤200 不拆
TOC_SEARCH_PAGES15目录只在前 15 页内找
前 4 页(0–3)无条件解析之后页面须含"节章部篇/一、二、…"关键词才解析
页码合法性[1,500]目录条目页码越界丢弃
章节名≥3 字且 ≠当前物理页否则丢弃
拆分点下限≥5跳过封面/首页
兜底按 200 硬拆找不到合适章节时

文件命名隐患：拆分名 {stem}-1.pdf/-2.pdf 与 mineru_client.batch_extract 推断分块起始页的正则 p(\d+)-\d+\.pdf$ 永不匹配 → 实际恒走 page_offset+1 分支（恰好可用，属隐式约定）。

4.1.2 Chunker 四大区块（chunker.py）

场景规则/阈值

业务描述overview 区间全文前 3000 字符
核心表粗筛有日期列（命中 12月31日/年度/3月31日/6月30日/9月30日/第一季度/上半年/前三季度）∧（有"附注"列 ∨ 季报）——注释称 216 张表实测 0 误报 0 漏报

参数值

4.1.4 OCR 纠错（text_corrector.py）

字典 + 单次编译正则（长匹配优先）：修复"资釐→资金、负偾→负债、收亼→收入、税釐→税金、应攵→应收、借欯→借款、现釐→现金"等形近字，以及数字混淆 OO→00, o0→00, l,→1,, S,→5,, T,→7,；[–—](\d) → -\1 归一全角负号。

高风险点：存在单字无上下文全局替换 巳/己→已、末→未、午→年、曰→日，会误伤正常词（"自己"→"自已"、"年末"→"年未"、"下午"→"下年"）。作用于切分前整篇文本与所有单元格。

环境耦合：mineru_client.py:21 硬编码 C:\Users\xu\.mineru\bin\mineru-open-api.exe（其它机器不存在 → 必然抛 FileNotFoundError → 自动降级 pdfplumber）。鉴权仅用 MINERU_TOKEN。

4.1.5 页码口径不一致（注意）

MinerU 单块路径用 page_idx（0 基）；分块路径经 batch_extract +1 归一 1 基；pdfplumber 恒 1 基。chunker 的"≤10 页忽略"在 0/1 基下跳过页数会差一页。

4.2 A 层 — 行业定性 + 同行基准（layer_a_benchmark / layer_amacro）

A1 行业标签（a1_tagging.py）— 纯代码 CSV 查表，无 LLM

  • 数据源：data/industry/sw_industry_classification.csv（申万行业分类，脚本 scripts/build_industry_csv.py 从 cninfo 申银万国分类树拉取）；必需列 股票代码/股票简称/所属申万一/二/三级行业。
  • 匹配：股票代码精确 → 失败按公司名双向子串包含模糊匹配 → 仍失败返回空硬标签（不降级）；行数 <5000 告警。
  • 产出标签：三级（system="申万三级行业"）/二级/一级，缺的级别不发标签。

A2 同行匹配（a2_matcher.py）— 纯代码 akshare + 余弦，无 LLM

流程：取二级行业作同行池（必要时用三级反查二级）→ 并发拉目标+全部同行 akshare → 全样本稳健统计量 → 逐行稳健标准化 (x−median)/IQR（IQR 下限 1e-10 防除零）→ 逐维取中位数得 6 维向量 → 余弦相似度排序 → 产出 Benchmark。

常量值
_PEER_COUNT_MIN5 家（MAD 基准池下限）
_TOP_PERCENT0.2 → MAD 池 = max(ceil(20%×N), 5)；同行 <10 家退化为 Top5
展示 Top余弦 Top5（供 E 层"同行对比"）
取数范围仅年报（report_type 含"年"），只保留最近 MAX_YEARS=5 年
网络akshare 单请求超时 25s；ThreadPoolExecutor(max_workers=6) 并发
后缀6→.SH；0/3→.SZ；4→.BJ
精度相似度/同行中位数 round 4 位
相似度判定只有相对排序，无绝对阈值；余弦=0 仅当任一方零范数
语义错位（重点，写文档必提）：名义 6 维含"研发费用率/销售费用率"，实际东财列映射为 YYZSRGDHBZC（注释自述"替代：营业收入同比增长率"）与 ROEJQ（"替代：净资产收益率-加权"）。真实 6 维 = 毛利率、净利率、总资产周转率、资产负债率、营收同比增速、加权 ROE。字段名语义 ≠ 取数语义，是旧字段名+新取数遗留。PeerCompany.similarity_score 注释"软标签相似度"实为财务向量余弦。

注意：peer_median 与 PeerCompany.financials 均以东财列名为键；financials 只取各同行最新一年原始值（C 层"同行中位"基于最新年报，非 5 年中位）。historical_mean 恒空（{ }）。

4.3 B 层 — 财务数据提取（layer_b_extract）

顺序：B0 表头语义指引 → B1 数值提取 → 勾稽校验。合并与母公司报表彻底分桶、分别产出 TableGuide / FinancialStatement。

4.3.1 B0 表头语义指引（b0_semantic_guide.py）

对每张报表做：布局检测 → 多级表头解析 → 字段映射。LLM 优先（client.chat("b0_semantic_guide", temperature=0.0, max_tokens=16384)，读表头与科目名、不读数值单元格，输入字段采样上限 100——注释与代码(50 vs 100)不符）；失败降级 _rule_based_guide（用 financial_fields.yaml 变体索引：col_0 全字优先 + 子串兜底）。

规则值
布局判定前 5 行最大列数 ≥3 → row_major（docstring 写 ≥6 与实际 3 不符）；否则 column_major
表头解析行数前 ≤10 行；找不到表头默认前 3 行
列名别名表期末余额/期末数/年末余额→end_balance；期初→begin_balance；本期发生额/金额→current_amount；上期/上年同期→prior_amount；金额→amount；占比→percentage；End Balance 等英文同义
单位正则顺序万元|万 → 千元 → 亿元 → 百万元 → 元/RMB/CNY（注意"万亿"会先命中"万"，顺序敏感）
report_type由"桶"归属强制决定（合并/母公司），_detect_report_type 结果被覆盖，属冗余
数值列兜底找不到数值列默认第 1、2 列；默认单位"元"

4.3.2 B1 数值提取（b1_extractors.py）— 纯代码

  • 入口按 table_guide.report_type 选合并/母公司桶；行式走 _extract_row_major，列式走 _extract_column_major。
  • 行命中多值取绝对值更大者（合并>母公司>附注小表）；子串误匹配规避：含"归属于母/少数股东"的行跳过；^[一二三四五六七八九十]+[、.，,]\s*\d+$ 视为附注引用"七、1"不取数。
  • 金额精度 _MONEY_QUANTIZE=0.01（2 位小数 ROUND_HALF_UP）；百分比串 ÷100；超 1e15 判解析错误返回 None。
  • 单位→倍数表：元=1 / 千元=1000 / 万元=1e4 / 百万元=1e6 / 亿元=1e8；未知单位回退 1。
  • _cross_validate_and_fix：合并/母公司资产负债表恒等式三缺一推算（缺一项由另两项反推）。
  • 交叉验证偏差分级：>5%（0.05）记异常（疑单位换算错）；1%–5%（0.01）仅 info 提示。
  • 8 个关键合计字段（_KEY_TOTALS）：资产总计、负债合计、所有者权益合计、货币资金、存货、营业收入、净利润、经营活动现金流量净额——用"科目列 col_0 全等匹配 + 固定列优先级 (col_2, col_3, col_1)"（假定 col_2=本期/期末）确定性提取，总是覆盖 LLM/补充结果，规避"负债合计误中流动负债合计"类子串问题。
  • 负值合理性白名单：Total_Assets / Monetary_Funds / Inventory 为负记异常。

4.3.3 勾稽校验（b1_validators.py）— 纯数学

恒等式规则性质
资产 = 负债 + 权益TOLERANCE=0.01（相对偏差 <1% 通过）；任一字段缺失→直接判失败（强制项）强制
期末未分配利润 ≈ 期初+净利润−分红同 1% 容差；缺期初/净利任一→自动通过（软项）；分红取资产负债表 Dividends_Payable（代码变量名 cashflow_dividends 易误导）软项

阻断语义：任一恒等式失败 → is_valid=False，错误文案"PDF 数据源可能损坏或造假"。orchestrator 因 errors 终止整条流水线，B+ 因门禁也自跳（README 的阻断机制与代码一致，只是真正写 errors 的是 B1）。

4.4 B+ 层 — 内部逻辑检查（layer_bplus_internal）

只代码、无 LLM。门禁：validation_passed=False → 整体跳过。流程：取三级行业 → _detect_soe 判国企/民企 → run_all_checks（①净现比/收现比 ②存贷双高 ③母子资金分离 ④销售增长vs现金流背离 ⑤过度投资）→ run_extended_checks（fraud_patterns，7 项 + Beneish M-Score）→ run_internal_control_check（内控四项，关键词 guess）→ 按白名单分 data/behavior → calc_risk_level。

行业阈值加载：config/industry_thresholds.yaml（相对 CWD 加载，非 __file__ 锚定；config/thresholds.yaml 对 B+ 属死加载）。判定规则见 §9 与下表。

检查判定规则（关键阈值）严重度 severity
①净现比/收现比（利润含金量）两者同时 <行业 p75（净现比默认 0.85 / 收现比 0.95），或两者同时 <0.6（经验双条件）极严重（净现比 <p25 或 <0）→ 5.0；否则 2.5

4.5 C 层 — 偏差计算（layer_c_deviation）— 纯代码

C 层不选同行，直接消费 A2 的 Benchmark（peer_median + peer_companies）。判定量：偏离倍数 = |实际 − 同行中位| / 稳健尺度（mad_calculator.py:122）。

项值/规则
尺度选择同行数 n ≥ _SMALL_SAMPLE=8 → 用 Sn 估计量；n<8 → 用 MAD
Sn 一致性因子_SN_CONSISTENCY = 1.1926（Rousseeuw & Croux）；实现为近似 Sn（偶数 n 未做中位两值平均；自称 O(n log n) 实际 O(n² log n)）
异常阈值偏离倍数 ≥2.0 判 abnormal；≥5.0 判 extreme（mad_calculator.py:261-322）
同行不足 Bootstrap 复核n_peers <15 且初判>2.0 → 1000 次重采样取 95% CI 下界 lo（n<5 粗暴返回 [0.5σ,2σ]；lo≤0→max(1e-6,最小正)；hi≤lo→hi=2lo）→ 用 lo 重算倍数 <2.0 → 判为虚报降级、跳过不报
边界同行全同值 → scale=0 → 偏离倍数=inf → 直接 extreme（并绕过 bootstrap，属病态案例）
指标实际值由桥接公式从原始财务字段算 5 个东财比率码：XSMLL=(营收−营业成本)/营收×100；XSJLL=净利/营收×100；TOAZZL=营收/总资产；ZCFZL=负债/资产×100；ROEJQ=净利/权益×100；未覆盖指标（如 YYZSRGDHBZC 营收增速，需跨年故注释显式跳过）→ 兜底直接字段名匹配，算不出跳过
时序突变 Pettitt实现存在（p<0.05，n<20 乘保守因子，n≥4）但默认管线未接线=死代码（__init__ 调用未传 historical；Benchmark.historical_mean 形状也不匹配）
注意：deviation_scorer.py（rank/filter/group/summary 工具）整个模块未被当前流水线调用；截面判 extreme 用 >=5.0 而时序路径用 >5.0，口径不一致。

4.6 D 层 — 原因推理（layer_d_reasoning）

注册顺序 D1→D2→D3，每异常处理。单个异常全程约 3 + 归因条数 次 LLM：D1 两路各 1 + D2 合并 1 + D3 每归因 1。

4.6.1 D1 双路径（d1_dual_path.py）

  • 路1 查原文解释（d1_lookup_notes.py，prompt d1_lookup_notes）：把 MD&A 各节 + 附注全量原文整段发给 LLM，不做关键词预过滤；解析取 sources[0] 为主来源，location 正则抽页码；is_vague 硬编码 False。
  • 路2 外部推演（d1_hypothesis.py，prompt d1_hypothesis）：输入 = macro_facts（无则占位）+ 行业 hard_tags + 主营业务描述；偏离度本地重算严重度（≥5 极端 / ≥2 显著 / 轻微）；来源 type 去重拼接为 reasoning。
  • 每路结果在 D1 即截断前 5 条；按 LLM confidence_rank 升序排序（非"权威性×共识"——那只用于 D2 m₂ 权重）。
隔离表述漏洞：路2 用的 business_desc 取自 raw_doc.company_overview.business_description，即路2 实际拿到一份 raw_doc 派生字段（仅主营业务描述，非 MD&A/附注）。

4.6.2 D2 概率分配（d2_probability.py）— D-S 证据理论（数学为纯代码）

参数在 config/thresholds.yaml → d2_layer:（epsilon_1=0.35 / epsilon_2=0.30 / path1_split_primary=0.70 / secondary=0.30 / path2_top_n=5 / conflict_threshold=0.60）。

  1. Step0 语义合并+冲突（LLM，prompt d2_merge_conflict）：把两路归因编成 merged_causes{name, path1_indices, path2_indices, conflicts_with}。失败即 raise（docstring 与实现相反），真正的批级降级在 layer_d/__init__：整批替换为 {"信息不足":1.0}。
  2. Step1 路1 mass m₁（纯代码，pool=1−ε₁=0.65）：k=0→Θ=1；k=1→0.65；k=2→主因 0.65×0.70=0.455、次因 ×0.30=0.195（谁主谁次由 LLM 列表顺序定）；k≥3→指数衰减每项拿剩余一半、末项拿光；末尾 m₁[Θ]=0.35。
  3. Step2 路2 mass m₂（纯代码，pool=1−ε₂=0.70）：对每归因算 consensus_weight = source_authority(最高)×source_count_bonus；权威映射（代码硬编码）：券商深度报告=1.0 / 官方公告=1.0 / 行业新闻=0.7 / 财经媒体=0.7 / A0宏观=0.6 / 行业常识=0.5 / 雪球股吧自媒体=0.3 / 其余 0.1（子串短路匹配）；数量奖励：≥3 来源→1.0 / 2→0.7 / 1→0.4 / 0→0.2。按 cw 降序取 top_n=5，归一后 ×0.70，m₂[Θ]=0.30。
  4. Step3 Dempster 合成（非标准变体，纯代码）：同名→累加；Θ×项→分给另一方；Θ×Θ→Θ；仅 conflict_map 中明确互斥的对才计入冲突 K；两个未被标记冲突的不同归因 → 整项并入 Θ（视为未知，而非标准 D-S 的空集冲突）。norm=1−K；norm≤1e-10（完全冲突）→ 返回 {Θ:1},K=1。severe_conflict = K>0.60（仅元数据标注，不影响数值）。
  5. Step4 Pignistic 转概率：Θ 不摊回，单列为"其他原因"桶（如 A44%/B30%/其他26%）；round 4 位后 Σ 偏差>1e-4 → 残差补到最大概率键。
配置脱钩：cfg["path1_split_primary"] 从未被传入 _build_m1（用函数签名默认 0.70，恰与 config 同值）；cfg["path1_split_secondary"] 全文无引用（次因由 1−primary 推导）。改 config 这两项不生效。

4.6.3 D3 语义匹配（d3_semantic_matcher.py）

对每异常每归因单独调一次 LLM（prompt d3_semantic_match，把整份 semantic_scoring.yaml levels 塞给模型选档）。"取最严重"没有代码实现，完全压在 prompt 里。代码只做：特例 "其他原因" → 免 LLM 返回 (0, ["其他原因"])；校验返回档位 ∈ {−3,−2,−1,0,1,2}，越界强制改为 −1；matched_keywords 截断最多 3 个。语义档库见 §10。

4.7 E 层 — 评分与报告（layer_e_output）

顺序 E1（纯代码算分）→ E2（组装报告 + 少量 LLM 文本润色）。重要：E1 完全不读 config/weights.yaml（WEIGHTS_PATH 声明未用，见 §12）。

4.7.1 E1 打分（e1_scoring.py）

基础分 100，逐异常累加扣分（可为负到负分）： anomaly_score = w_phe × (1−K) × Σ P(Hᵢ)·S_base(Hᵢ)

  • w_phe（现象严重性）：B+ 异常=其 severity（0.5–5.0）；C 异常 = min(mad_multiple/3.0, 5.0)。
  • delta = 1 − K（K=D-S 冲突系数，缺失默认 0）；score_base 取 D3 语义档（缺省 −1）；effective_score = score_base × delta。
  • 找不到对应 D 推理（按 (source, indicator) 精确匹配）→ 该异常静默跳过不计分（仅 warning）。
  • Bel/Pl 上下界：m_theta=mass_final["Θ"]，known=1−mθ；若 mθ>0 且语义档非空：悲观把 Θ 全给 S=−3 → score_bel（最大扣分），乐观把 Θ 全给 S=+2 → score_pl（最小扣分）；否则三点相等。命名逆直觉：bel=下界分（更差）、pl=上界分。
  • 总分 = 100 + Σ anomaly_score；最终 [Bel, Pl] = [100+Σbel, 100+Σpl]（lower=min(total_bel,center)，upper=max(total_pl,center)）。
  • 置信度档：score ≥80 → 高置信度；≥60 → 中等置信度；否则低置信度（e2_report_gen.py:199）。

TrustInterval 展示（e2_report_gen 聚合）：avg_k=ΣK/count；avg_m_theta 由 diff=2·w_phe·delta·5 反推——公式额外多除 2，展示性偏小（不影响分数）。

5.2 参数 / 重试 / 边界

  • 重试：max_retries=3；401/403/unauthorized 不重试直接抛；429 → 指数退避 2^(attempt+1)（2s、4s）；其它错误 wait=1s；timeout_seconds=300。

  • max_tokens 兜底：anthropic/openai 4096；deepseek/glm 未显式限长被"上限保护"改为 16384。
  • 原生思考链：NO_THINKING_PROMPTS={"b0_semantic_guide"}（仅对 OpenAI 兼容厂商 extra_body={"thinking":{"type":"disabled"}} 关闭）；Anthropic 侧无开关。推理类 prompt（表分类、d1/d2/d3）保留思考链，reasoning_content 流式进 tracer。
  • 缓存：仅 PromptLoader 对 prompt 模板进程内缓存，无 API 响应缓存。
  • token：优先 API usage；缺省估算 len(text)//2。cost 表只含 5 个模型（claude-sonnet-5 3/15、claude-opus-5 15/75、gpt-4o 2.5/10、gpt-4o-mini、deepseek-chat）——默认模型 deepseek-v4-flash 不在表内 → 估费恒 0。
  • B0 语义指引是唯一经 Pydantic schema 校验？——否：B0 实际手解析；各 LLM 返回多靠 response_parser.parse_json（剥 fence、单引号转双引号）手写容错。

9. 行业阈值机制详解（B+）

数据结构：industries.<行业名>.{net_profit_cash_ratio_p25/p75/median, sales_cash_ratio_p25/p75/median, cash_to_assets_p75/p70/avg, debt_to_assets_p75/p70/avg, fund_separ_mean/std}，部分含 note 与 skip_checks；顶部有 fallback:。示例（白酒）：净现比 p25 0.55 / p75 1.10 / 中位 0.85；货币资金占比 p75 0.42；有息负债占比 p75 0.18；母子分离 mean 0.08 / std 0.04。金融行业（银行/城商行/证券/保险）净现比/收现比多为 null + skip_checks:["净现比","收现比"]。

  1. 加载与缓存：_load_industry_thresholds 结果缓存模块级；cfg 有效判据含 skip_checks/note 等非 None 字段 → 银行全 null 块仍判"有效"，阈值再由 _get_ind_threshold 逐 key 落默认值。
  2. 逐 key 取值链：行业配置值 →（key 含 p75 则试 p70×1.2 推算）→ 函数默认参数（净现比 p75 0.85 / 收现比 0.95 / 存贷 0.30·0.42 / p25 0.25）。
  3. 规模修正（按总资产 ≥40亿 大型 / ≥5亿 中型 / else 小型，缺资产默认大型）：下尾阈值（p25/净现 p75）小型 ×0.65、中型 ×0.82；上尾（cash_to/debt_to 的 p75）小型 ×1.30、中型 ×1.15。语义：净现比/收现比对小公司放宽；存贷双高对小公司收紧。
  4. skip_checks 仅一处使用：run_all_checks 对"净现比"门控 ① 检查；存贷双高/母子分离不受 skip 影响。→ 银行等天然高杠杆下存贷双高仍会跑且落全局默认（YAML 注释称"用专项指标替代"，代码未实现专项）。
  5. 代码默认值 ↔ YAML fallback 双写，当前一致（p25 0.25 / p75 0.85 / cash p75 0.30 / debt p75 0.42 / mean 0.10 / std 0.06）。
  6. 数据来源（注释口径）：akshare 全 A 近 5 年统计，季度随财报季更新。另 scripts/build_industry_quantiles.py 能生成 industry_quantiles.yaml（p05–p95/mean/std），但当前未被任何代码消费；其中"规模分层"实际按代码枚举顺序三等分（非真实总资产，循环体 pass），分位数回归为占位符。

10.2 E1 最终数学

final_score = 100 + Σ_{异常 i}  w_phe(i) · (1 − K_i) · Σ_{归因 H}  P(H) · S_base(H)
bel_lower   = 100 + Σ  w_phe · delta · [ (mass_raw + m_θ·(−3)) / (1−m_θ) ]   # 悲观: Θ→S=−3
pl_upper    = 100 + Σ  w_phe · delta · [ (mass_raw + m_θ·(+2)) / (1−m_θ) ]   # 乐观: Θ→S=+2
置信度:  ≥80 高  /  ≥60 中  /  其余 低

mass_raw = Σ cause_mass×S_base；GLOBAL_S_MIN=−3 / MAX=+2。扣分不设下限（总分可为负）；B+/C 异常各以 (source, indicator) 精确对齐 D 推理，缺推理即跳过。
